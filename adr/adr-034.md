# ADR-034: Declaring and Conforming to `trait`s and `role`s

[ADRs](./README.md)

> Adopted

## Context

[ADR-009](./adr-009.md) introduces `trait` and `role` as abstract types but does not define their syntax, how an `object` declares conformance, or how calls through them are represented and executed.

## Decision

### Syntax

```clawr
trait Shape {
    func area() -> integer
}

object Square: Base, Shape {
    func area() => 4
}
```

- A `trait`/`role` body contains only method signatures: no bodies, no initializers, no state ([ADR-014](./adr-014.md)). Parameters and result must have explicit value sets.
- After `:`, an `object`/`service` lists a comma-separated set of names. If the first name is an `object`/`service`, it is the supertype and the rest are `trait`s/`role`s. Otherwise all names are `trait`s/`role`s. A type has at most one supertype.
- A `trait`/`role` may be declared anywhere in the module. A supertype must be declared before its subtypes.

### Conformance rules

- Every requirement must be implemented by the type itself or inherited from its supertype.
- Parameters must match exactly. The implementation's result may be narrower (a subset) than the required result.
- A `service` may conform only to `role`s. An `object` may conform to both.
- Naming the same interface twice, or a name that is not a `trait`/`role`, is an error.

### CIR

- An `INTERFACE_DECL` lists the required signatures.
- Each `RC_TYPE_DECL` lists `conformances`, mapping every requirement to the implementing method.
- A call on a value typed as a `trait`/`role` uses `dispatch: 'conformance'`, and the receiver's type is an `interface` value set.

### Runtime (planned, backend not yet implemented)

An interface-typed value is an ordinary reference. The backend finds the conformance table through the object's type information (`header->is_a`), keyed by interface identity. There are no fat pointers, so a value can be passed to and stored as any conforming type without conversion.

## Consequences

- Dispatch through interfaces needs no change to value representation.
- A lookup by interface identity is slightly slower than a fixed vtable slot.
- A subtype does not yet inherit its supertype's conformances; it must name the interface again.
- `mutating` requirements and conformance of `data` and boxed types are not yet defined.
