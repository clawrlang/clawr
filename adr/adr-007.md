# ADR-007: Three-valued Logic Operators

[ADRs](./README.md)

## Status

💡 **Proposed**

> An idea to be considered for adoption

## Context

The three-valued `truthvalue` begs for logical operators beyond the traditional Boolean set.

## Decision

The traditional Boolean operators AND (`&&`), OR (`||`) and NOT (`!`) remain usable for `truthvalue` expressions, but XOR ( `^`) is removed.

The following additional “operators” are added:

- `rotate(a, by: b)`
- `adjust(a, towards: b)`
- `modulate(a, by: b)`

The three operators (in order) represent mod-3 addition, clamped addition and multiplication when considering the field {-1, 0, 1} = {false, ambiguous, true}.

- Modulation (multiplication) by `false` = -1 flips the digit of the other value, effectively creating a NOT gate. Modulation by `true` creates a pass-through gate and modulation by `ambiguous`forces ambiguity.
- Adjusting a value towards `true` makes it one step more truthful (unless it already is `true`). Adjusting towards `false` makes it one step less truthful. Adjusting towards `ambiguous` returns the value unchanged.
- Rotating is similar to adjustment except that the value falls over the edge (or “rolls over”) to its opposite if both inputs are equal.

## Rationale

- [ADR-000](./adr-000.md) mentions ternary computing as an inspiration for creting the language. Ternary computers are expected to use ternary logic naively.
- XOR has no canonical implementation for three-valued logic.
- It would be awkward to support XOR for scalars, but not for fields.

## Alternatives Considered

- Support XOR for the `truthvalue(true|false)` subset (a.k.a. `boolean`) only.
- Define XOR in the terms of the fundamental operators: `a ^ b -> (a && !b) || (!a && b)` rather than mod-2 addition.
