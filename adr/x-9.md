# ADR-X09: Types as Sets

[ADRs](./README.md)

## Status

✍🏼 **Draft**

> A rough sketch of an idea

## Context

The `integer` and `real` types support lattices (subsets) based on ranges. Such a range might be useful to declare officially. The `truthvalue` type has only three values/states and supports enumerated lattices selecting any one, two or all of said states.

> [!warning]
> The `real` type is not yet formalised. It needs precision. Is that part of the lattice or a separate property? That might affect how we define `subset` here.

## Decision

Primitive types support declared and implied subsets (“lattices”). The `integer` type represents the countably infinite set ℤ, and the `real` type represents the uncountable set ℝ. The `truthvalue` type represents the set containing three truth-values `false`, `ambiguous` and `true`.

Variables, fields, parameters and return-values can be declared as supporting the entire set or just a subset. If a value outside the specified range is assigned to the variable, that is an error and the static analyser must catch it.

The static analyzer must also track the set of possible values for each expression so that it can detect when the value-set exceeds the allowed subset.

For the numeric lattices, a sublattice is represented as a range (`min`/`max`). The range can be open-ended in either direction. For `truthvalue`, a subset is an enumeration of one, two or all three states.

The term “lattice” is a near-synonym to the word “set.” The difference is that two lattices can be *joined*, while two sets are *unioned*. The union of two sets creates a subset with all the existing elements and no other. A join of two lattices might add additional elements. It our case, we merge two integer ranges into one large range. If there is a gap between the ranges, the joined lattice includes that gap.

Example:

$$[0, 10) \vee [15, 20) = [0, 20)$$ 
but:

$$[0, 10) \cup [15, 20] \not = [0, 20)$$

Here  $\cup$ means “union of sets,” and $\vee$ means “join lattices.”

```
integer(0..<10) join integer(15..<20) == integer(0..<20)
integer(0..<10) union integer(15..<20) cannot be reduced
```

We are only interested in saying that the value is between 0 and 20, not that it cannon be in the subrange $[10, 15)$. That information does not help anybody.

## Rationale

- A type declaration in any programming language is in effect a lattice constraint – it defines limited set of valid values.
- An inheritance class in a traditional OO language is effectively a subset to its superclass.
- Lattices allow more fine-grained (and spatially dependent) resolution of compatibility than a simple types do.
