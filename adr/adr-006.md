# ADR-006: Ad Hoc Data Structures

[ADRs](./README.md)

## Status

💡 **Proposed**

> An idea to be considered for adoption

## Context

Modern languages often support tuples; a kind of fixed-length heterogeneous array of items where each position has a predetermined type.

## Decision

The data-literal syntax, `{ field: value }` can be used to return values in an ad-hoc fashion similar to TypeScript’s type notation. They can also be used as the cases of a `union` type.

## Rationale

1. While tuples are useful for rapid prototyping, they are not very expressive. Labelling the items make them more parsable for humans.
2. Ad hoc types are however often desirable in APIs.

## Alternatives Considered

- Using tuples as a prior art.
- Not supporting any ad hoc return types at all, but allowing only named types.

## Consequences

### Positive

- Expressive syntax

### Negative

- Not yet solved, might be hard to implement
