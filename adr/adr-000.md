# ADR-000: Platform Agnostic Language

[ADRs](./README.md)

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

Recently, there has been talk of ternary chipsets. Modern languages — typically based on C and LLVM — typically work with data types that assume binary architectures. Not judging the feasibility of ternary in the immediate future, Clawr should still be ready for multi-base architectures.

Traditional languages conflate numerical integers with fields of bits. Bitwise and arithmetic operators can be applied to the same data because numbers are stored in binary form. This is not true for Clawr.

## Decision

Integer and floating-point variables are defined abstractly — not by their size in bits nor even by the IEEE 754 standard. The programmer selects ranges and precision through the syntax and the compiler (backend) might choose optimized storage based on the target platform.

An `integer` cannot be used as a field, and a field cannot be used as an `integer`. Though some form of explicit conversion might be allowed.

## Rationale

1. The same Clawr source code should run equivalently on binary and ternary hardware
2. Arithmetics and bitwise operations are fundamentally different animals.
3. Bitwise binary operations on ternary-encoded integers (or vice versa) would be nonsensical.

## Alternatives Considered

- None. This is a founding idea for the language
