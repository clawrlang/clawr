# ADR-039: Control-Flow

> Status: ✅ Adopted

## Context

A general-purpose programming language needs control-flow mechanics.

This separates procedural languages from declarative languages. A declarative language like VHDL or Haskell declare truths that must be fulfilled at all times (“invariants”). It cannot describe interactions except in the shape of data structures that model them. A procedural language defines operations that a program may perform and the algorithms that ensure that the invariants are maintained throughout execution.

Clawr supports three-valued truth. This affects how control-flow is defined. According to [ADR-006](./adr-006.md), the `ambiguous` state is not `true` and should be considered `false` in control-flow statements. But so should `!ambiguous`, because `ambiguous` is not actually `false`.

## Decision

Clawr supports `if`/`else`, `while`, `repeat`/`while`, and three-valued logical negation. Their current rules are defined in [Control Flow](../spec/language/control-flow.md), with CIR contracts in [`IF`](../spec/cir/statements/IF.md), [`LOOP`](../spec/cir/statements/LOOP.md), [`NOT`](../spec/cir/expressions/NOT.md), and [`SCOPE`](../spec/cir/expressions/SCOPE.md). Source short-circuiting is encoded by the frontend; CIR `AND`/`OR` are eager.
