# ADR-006: Three-valued Truth

> Status: ✅ Adopted

## Context

[Three-valued logic](https://en.wikipedia.org/wiki/Three-valued_logic) has many flavours. One canonical philosophy must be chosen for Clawr

The philosophical models of three-valued logic are defined by how they consider _material implication_ — a problematic concept in its own right. You can however infer that [Stephen Cole Kleene](https://en.wikipedia.org/wiki/Stephen_Cole_Kleene) considered the third state **neither** true **nor** false, while [Jan Łukasiewicz](https://en.wikipedia.org/wiki/Jan_%C5%81ukasiewicz) considered it **both** true **and** false.

## Decision

`truthvalue` has three states: `false`, `ambiguous` and `true`. `ambiguous` counts as `false` in control flow, and `&&` and `||` return the least and most true operand respectively. Equality is two-valued, so the logic is a close sibling of Kleene logic rather than an implementation of it.

> [!note]
> The rules themselves are defined in the specification: [Logic Operators](../spec/language/types.md#logic-operators). This ADR records only the reasoning.

> [!note]
>
> Kleene and Priest logics, and the Łukasiewicz Ł3, are defined by how they consider _material implication_ — a problematic concept in its own right — rather than what the third state _means_ according to their respective philosophies. It is therefore not quite true to say that this is an implementation of Kleene logic even though the idea that the unknown/ambiguous state in both cases is considered neither true nor false.
>
> Unlike the Ł3 which considers the unknown state **both** true **and** false.

## Rationale

- [ADR-000](./adr-000.md) mentions ternary computing as the original inspiration for creating the language. Ternary computers are expected to use ternary logic natively.
- `if (x)` naturally reads “if x is true,” rather than “if x is not false.” Treating `ambiguous` as sort-of-`true` feels incorrect.
- Short-circuiting is expected based on the prevalence of prior art. When the first part of the expression evaluates to the Boolean subset (not `ambiguous`), the logical conclusion will closely match the binary model.

## Alternatives Considered

- the Łukasiewicz Ł3 is deemed not useful for automated decision-making, as `ambiguous` would be both `true` and `false` at the same time.
- Ordinary Boolean datatype.
