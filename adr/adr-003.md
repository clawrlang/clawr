# ADR-003: `UNIQUE` Return Values

> Status: ✅ Adopted

## Context

Allocated (reference-counted) memory come in two variations: `ISOLATED` and `SHARED`. A function cannot know the intended recipient of its returned data.

## Decision

A returned structure carries a reference for the recipient. An `ISOLATED` value without other references can be returned as uniquely referenced (`UNIQUE`); `SHARED` data cannot.

Primitive values (`integer`, `real`, `truthvalue`, `string`) are always `ISOLATED` and cannot be returned as `UNIQUE` unless they are boxed.

> [!note]
> The rules themselves are defined in the specification: [Isolation Levels for Function Return Values](../spec/language/semantics/return-values.md). This ADR records only the reasoning.

## Rationale

1. A function cannot know the intent of its caller.
2. `SHARED` data will never have only one reference in practical situations. They are typically stored as properties, and the property will always need to count a reference. The recipient variable is at minimum a second reference.

## Alternatives Considered

- Return values could always be `ISOLATED` or explicitly `SHARED`.
