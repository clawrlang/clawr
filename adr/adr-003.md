# ADR-003: `UNIQUE` Return Values

[ADRs](./README.md)

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

Allocated (reference-counted) memory come in two variations: `ISOLATED` and `SHARED`. A function cannot know the intended recipient of its returned data.

## Decision

A function can declare parameters without specifying semantics. These will have `UNKOWN` isolation-levels.

A reference-counted value with `UNKOWN` isolation level cannot be assigned to another variable. There is no (static) way to ensure that the assignment does not break isolation guarantees.

An `UNKNOWN` parameter is readonly. It is not safe to modify without first copying, and applying copy-on-write to a `SHARED` instance is also fraught.

## Rationale

1. A function cannot know the intent of its caller.
2. `SHARED` data will never have only one reference in practical situations. They are typically stored as fields, and the field will always need to count a reference. The recipient variable is at minimum a second reference.

## Alternatives Considered

- Require all parameters to have explicit isolation levels
- Default (no-keyword) parameters to `const` semantics
