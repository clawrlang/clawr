# ADR-004: Syntax, Semantics and CIR

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

Compilers are typically designed in two main subsystems: a frontend and a backend. The frontend handles parsing and semantic analysis, while the backend “lowers” the program or library to machine code.

## Decision

Clawr is defined as its syntax and semantics only. There is no official Clawr compiler but teams can build their own, targeting various platforms and employing various strategies for optimization.

The semantics is communicated in a tightly defined intermediate representation (the CIR) so that the frontend and backend can be developed by independent teams.

## Rationale

1. To support many platforms the backend must be customizable. A single official Clawr team cannot be expected to know how to lower to all available platforms.
2. There may be various optimization strategies. Teams can choose their own.

## Alternatives Considered

- Create an official library implementation for the frontend and let backend developers build the compiler executable using the library.
- Create an official compiler and make the lowering step a plugin.

## Consequences

### Positive

- Clawr can spread quickly to many platforms.
- Compiler developers can perform different optimizations for different chipsets.
- New optimization ideas can be tested easily.
- Compiler developers can focus on either the frontend or the backend

### Negative

- Requires tight specification of, and adherence to, the CIR. Developers must be able to trust the ecosystem.
