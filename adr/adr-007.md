# ADR-007: Serializable `data`

## Status

💡 **Proposed**

> A proposed idea

## Context

Data structures are often used as DTOs or for persistence. 

## Decision

Every `data` type should be serializable by default. A `trait` for custom serialization can be added. This trait can be used by `object` types as well, though they will not be serializable without it.

## Rationale

1. While tuples are useful for rapid prototyping, they are not very expressive. Labelling the items make them more parsable for humans.
2. Ad hoc types are however often desirable in APIs.

## Alternatives Considered

- Using tuples as a prior art.
- Not supporting any ad hoc return types at all, but allowing only named types.

## Consequences

### Positive

- Expressive syntax

### Negative

- Not yet solved, might be hard to implement
