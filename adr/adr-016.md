# ADR-016: Backend-Managed Boxing of Unboxed Primitives

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

[ADR-000](./adr-000.md) defines integers and floats abstractly. [ADR-005](./adr-005.md) defines them as
lattices, possibly constrained by ranges. [ADR-015](./adr-015.md) defines ARC for structures
and explicitly boxed primitives.

However, an unboxed primitive such as `integer` may be arbitrarily large unless
constrained by a lattice. The frontend cannot know whether a given value fits
in a machine word, nor when a backend will need to allocate or reuse a pointer
for it. Therefore the frontend cannot inject ARC operations for implicit boxing.

## Decision

Unboxed primitive values are not ARC-managed in the CIR. The frontend does not
inject `ALLOCATE`, `RETAIN`, `RELEASE`, or `ENSURE_UNIQUE` for them.

The backend chooses the concrete representation of primitive values. If a value
fits in an unboxed representation, the backend should prefer that. If it does
not, the backend may box or allocate internally.

Any such boxing is backend-private. It must preserve value semantics. No
observable pointer identity or aliasing may leak through the language
semantics. The backend owns the lifetime of these internal boxes and may use
reference counting, arenas, immediate values, or any other strategy, as long as
the observable semantics are preserved.

Explicitly boxed primitives are normal ARC-managed values and follow [ADR-015](./adr-015.md).

## Rationale

- The frontend cannot know backend representation thresholds.
- Keeping implicit boxing out of the CIR keeps the CIR platform-agnostic.
- Backends may use platform-specific arbitrary-precision integer libraries.
- Forcing ARC onto unboxed primitives would be premature and platform-dependent.

## Consequences

### Positive

- Backends are free to choose efficient primitive representations.
- The CIR remains simple and portable.
- Explicit boxing remains fully ARC-managed and predictable.

### Negative

- Backend bugs in primitive boxing are invisible to the frontend.
- Different backends may have different performance and memory behaviour for
  the same primitive operations.
- Debugging implicit boxing is backend-specific.
