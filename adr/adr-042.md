# ADR-042: Semantic Modifiers as Annotations

> Status: 📝 Proposed

## Context

Many languages provide visibility modifiers for controlling access to program elements such as classes, methods, and variables. There are also modifiers for other purposes, such as virtual methods, abstract classes, and final declarations.

All these modifiers add keywords to the language, which restrict what names programmers can use for their own declarations.

## Decision

Modifiers that affect the behavior or visibility of program elements will be expressed as annotations rather than as new keywords. Modifiers that influence the syntactic structure of the language remain as keywords.

Potential annotation modifiers include:

- `@helper` for restricting visibility or access to certain program elements.
- `@open` for indicating that a class or method can be extended or overridden.
- `@final` for indicating that a class or method cannot be extended or overridden.
- `@abstract` for indicating that a class or method is abstract and must be implemented by subclasses.

The `extern` modifier changes the structure of function declarations and `MUST` remain a keyword.

## Consequences

- Programmers will use annotations to specify modifiers instead of relying on new keywords.
- The language can introduce new modifiers without adding new reserved words.
- Existing code that uses keywords for modifiers may need to be updated to use annotations.
- Tooling and compilers will need to recognize and process these annotation-based modifiers appropriately.

## Rationale

The rationale for using annotations instead of keywords is primarily to avoid polluting the language with additional reserved words. By using annotations, the language can remain flexible and extensible, allowing new modifiers to be introduced without conflicting with existing identifiers. This approach also aligns with modern language design trends, where annotations or attributes are commonly used to convey metadata and behavioral hints to the compiler or runtime.

If the parser understands specific keywords, but not annotations, the separation between parsing and semantic analysis remains clear. Parsing's job is not to enforce semantic rules, but to recognize the syntactic structure of the code. Annotations can then be processed during semantic analysis to apply additional rules or behaviors without complicating the parsing stage.

Some modifiers, like `extern`, directly affect the syntactic structure of the language and must be recognized by the parser as keywords. Others, like `@helper` or `@open`, convey semantic information and do not affect the syntax.
