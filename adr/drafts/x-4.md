# ADR-X04: Discard Label `_`

[ADRs](../README.md)

## Status

✍🏼 **Draft**

> A rough sketch of an idea

## Context

The CIR currently defines two `CALL` nodes. One considered a `Statement` (with no return value) and one considered an `Expression`. By convention, all expressions `MUST` have a `value` lattice/subset, while statements `MUST NOT`. This means that functions that return a value cannot be called as statements, but their result must be `ASSIGN`ed or used as arguments.

## Decision

Convert `CALL` expression into an `ASSIGN` statement (or perhaps a `DISCARD_RESULT` statement) by assigning to `_`. Use `_` in lambdas etc to indicate an ignored parameter.

Make `_` a keyword (or reserved identifier).

## Rationale

The `_ =`  prefix clarifies that the function call produces a result and that discarding it is an intentional choice by the programmer.

If the result is reference-counted, it must be `RELEASE`d in the CIR. This behavior will be easier to implement if it is not discarded implicitly.

## Alternatives Considered

- Allow `CALL` expressions to be used as statements without explicitly discarding their result.
