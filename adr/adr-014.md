# ADR-014: Traits and Static

## Status

> Status: 💡 Proposed

## Context

A Swift `protocol` can define initialisers and other `static` members. Other languages restrict `interface` to declare instance methods only.

## Decision

A `trait`/`role` cannot define “static” elements.

Traits/roles cannot define static elements or initializers. Polymorphic construction is expressed via factory services/roles.

## Rationale

- Clawr focuses on sets, not types.
- Clawr prioritises expressing meaning over mechanics. The programmer should model the problem, not the solution.
- A `trait` defines an heterogeneous set of _values_ (and a `role` defines an heterogeneous/polymorphic set of services).
- Mixing type constraints would shift the focus from meaning to implementation.
- Initializers are type constraints, not value constraints.
