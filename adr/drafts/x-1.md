# ADR-X01: `subset`

[ADRs](../README.md)

## Status

✍🏼 **Draft**

> A rough sketch of an idea

## Context

The `integer` and `real` types support subsets based on ranges. Such a range might be useful to declare officially. The `truthvalue` type has only three values/states and supports enumerated subsets selecting any one, two or all of said states.

> [!warning]
>
> The `real` type is not yet formalised. It needs precision. Is that part of the value-set or a separate property? That might affect how we define `subset` here.

## Decision

The `subset` keyword defines a subset to the `truthvalue`, `integer` or `real` types.

- `subset boolean = thruthvalue(false|true)`
- `subset natural = integer(1...)`

Subset declarations do not propagate to the CIR. They are only aliases used by the frontend.

We might also define subsets to represent binary standard widths:

- `subset int32 = integer(-2^31..<2^31)`
- `subset uint32 = integer(0..<2^32)`
- `subset int64 = integer(-2^63..<2^63)`
- `subset uint64 = integer(0..<2^64)`
- `subset int128 = integer(-2^127..<2^127)`
- `subset uint128 = integer(0..<2^128)`

IEEE 754:

- `subset float16 = real(???)` (short)
- `subset float32 = real(???)` (float)
- `subset float64 = real(???)` (double)
- `subset float128 = real(???)` (quadruple)
- `subset float256 = real(???)` (octuple)

Balanced Ternary:

- `subset btint27 = integer(-(3^27-1)/2..<(3^27-1)/2)`
- `subset btint54 = integer(-(3^54-1)/2..<(3^54-1)/2)`
- `subset btint81 = integer(-(3^81-1)/2..<(3^81-1)/2)`
- ...

BT Floating-point:

- `subset btfloat27 = real(???)`
- `subset btfloat54 = real(???)`
- `subset btfloat81 = real(???)`
- `subset btfloat162 = real(???)`
- `subset btfloat243 = real(???)`

## Rationale

- Easy reuse for domain declarations.
- Seems like an obvious feature as subsets already play an important role.
