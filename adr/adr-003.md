# ADR-003: `UNIQUE` Return Values

[ADRs](./README.md)

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

Allocated (reference-counted) memory come in two variations: `ISOLATED` and `SHARED`. A function cannot know the intended recipient of its returned data.

## Decision

When returned from a function call, every structure must have a reference-count of at least 1 (for the assumed recipient) plus whatever other references remain after releasing the local variables of the function.

If an `ISOLATED` value is known to have no other references beyond the recipient, it can be flagged as `UNIQUE` instead of just `ISOLATED`. One way to ensure this is to “mutate” it (i.e. `ENSURE_UNIQUE`) before returning.

`SHARED` data cannot be returned as `UNIQUE`.

## Rationale

1. A function cannot know the intent of its caller.
2. `SHARED` data will never have only one reference in practical situations. They are typically stored as properties, and the property will always need to count a reference. The recipient variable is at minimum a second reference.

## Alternatives Considered

- Return values could always be `ISOLATED` or explicitly `SHARED`.
