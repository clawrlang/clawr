# ADR-019: `namespace`

[ADRs](./README.md)

## Status

💡 **Proposed**

> An idea to be considered for adoption

## Context

[ADR-018](./adr-018.md) removes `companion` from the construction process. What is a `companion` now?

## Decision

There is no real need for a `static` context in Clawr. We can emulate it using `namespace` rather than a `companion`. If the `namespace` has the same name as a type, it will be syntactically indistinguishable from a companion/static type context. It just will not have the privilege of seeing and manipulating fields.

Replace `companion` with two new concepts:

1. `service` factories using existing syntax, and
2. `namespace` that defines free functions and variables.

## Rationale

- Braces are a strong signal for `ALLOCATION` and initializaition.
- Express intent by freely naming initializers.

## Consequences

### Negative

- Reusing braces in supertype initialization might incorrectly signal multiple allocations.
- Requiring braces to invoke a constructor might feel weird.

### Positive

- Allocation becomes more explicit.
- Convenience factories are still allowed/possible.
- Initializers still read like methods (explicit and intentional) while distinct (with the brace syntax).
