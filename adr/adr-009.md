# ADR-009: Real Numbers

[ADRs](./README.md)

## Status

💡 **Proposed**

> A proposed idea

## Context

The implementation so far only supports integer numbers (ℤ). The uncountably infinite set of the reals (ℝ) is considered too complex to define pragmatically while supporting other numeric bases than binary.

## Decision

`real` functions like `integer`, except that it needs a precision parameter.

In the runtime, the unconstrained `Real` is implemented an exponent (for base 10) and a mantissa, both `Integer` values. In other words, the value is $m \times 10^e$, where $m$ it the mantissa, and $e$ the exponent.

Store mathematical and physical constants, such as π and e, with 50 digits. If the programmer needs more precision, they will have to implement it themself.

## Rationale

1. Real values are different from integers. They can have an arbitrary number of decimals.
2. A `role` that is expected to access a repository could store all of its data in memory — particularly useful in tests — which would make an `object` more suitable than a `service`.

## Alternatives Considered

- IEEE 754
- Represent constants symbolically or as infinite sums

## Consequences

### Positive

- Can support arbitrary siza and precision.

### Negative

- It is unclear how to specify precision need or how numbers should behave when assigned.
- Mathematical constants cannot be stored with an infinite decimal expansion so what precision to store is unclear.
