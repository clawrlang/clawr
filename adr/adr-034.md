# ADR-034: Declaring and Conforming to `trait`s and `role`s

> Status: ✅ Adopted

## Context

[ADR-009](./adr-009.md) introduces `trait` and `role` as abstract types but does not define their syntax, how an `object` declares conformance, or how calls through them are represented and executed.

## Decision

Use explicit interface requirements and named conformances, flattening interface inheritance in the frontend so the backend dispatches through canonical conformance tables.

> [!note]
>
> Current rules are defined in [Traits and Roles](../spec/language/user-types/trait-role.md#declaring-and-conforming-to-interfaces) and [`INTERFACE_DECL`](../spec/cir/declarations/INTERFACE_DECL.md). The example runtime's representation is described in the [backend guide](../guides/implementation/backend/README.md#interface-representation). This ADR records the reasoning.

## Consequences

- Dispatch through interfaces needs no change to value representation.
- A lookup by interface identity is slightly slower than a fixed vtable slot.
- A subtype does not yet inherit its supertype's conformances; it must name the interface again.
- `mutating` requirements and conformance of `data` and boxed types are not yet defined.
