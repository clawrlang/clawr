# ADR-015: Basic ARC Rules

> Status: ✅ Adopted

## Context

Large structures need a memory strategy.

## Decision

### ARC scope

`data`, `object`, `service`, and explicitly boxed primitives
are ARC-managed by the frontend/CIR.

Substructures are presumed heap-allocated with reference pointers in their
parent structures.

Copy-on-write: when an `ISOLATED` value is modified, it must first be copied unless it is uniquely referenced.

### Ownership and return values

A returned ARC-managed value carries a +1 reference for the caller.

The caller owns that +1 reference and must release it when it is no longer needed. The caller does not retain the value on receipt.

The callee must ensure that the +1 reference survives scope exit, typically by retaining the value before releasing local references.

### Parameter Passing and Retention Semantics

Parameters are borrowed by default. The caller does not need to retain them, and neither does the callee unless they escape the call context. The caller’s stack frame guarantees parameter lifetime for the duration of the call.

UNKNOWN parameters remain read-only per [ADR-003](./adr-003.md). If an UNKNOWN parameter is stored, it must be copied to ensure isolation.

### Copy-on-write

`ISOLATED` values are eligible for copy-on-write. Before modifying an `ISOLATED` value, the frontend must ensure it is uniquely referenced. That is done by invoking the `ENSURE_UNIQUE` statement.

Do not `ENSURE_UNIQUE` a `SHARED` variable as changes are supposed to affect all references.

### CIR operations

- `ALLOCATE` sets aside memory for a structure (excluding substructures) with a retain count of 1
- `RETAIN` increments the retain counter
- `RELEASE` decrements the retain counter and deallocates the structure if it reaches zero
- `ENSURE_UNIQUE` shallow-copies a structure for a variable or property — and reassignes the reference — if its retain counter is > 1.

The frontend injects these operations. The backend lowers them faithfully.

### Explicit vs implicit boxing

ARC applies to explicitly boxed primitives.

Unboxed primitives are not ARC-managed by the frontend/CIR. If a backend needs to box an unboxed primitive, that is backend-private. See [ADR-016](./adr-016.md).

## Rationale

- Frontend has all static analysis information; backend should be simple.
- Frontend cannot know whether backend uses stack allocation.
- Backend can ignore ARC for stack values, but cannot invent frontend knowledge for heap values.
- Return values must be retained across scope exit to avoid zombies.
- Callee cannot know the caller’s intended storage or lifetime.
- The caller is the natural owner of the returned value, and should be responsible for its release.

## Consequences

### Negative

- The frontend has to track retains and releases so that values neither leak nor turns into zombies.
- The backend has to track its own implicitly boxed primitives and retain/release them accordingly.
- The backend must faithfully lower ARC operations or prove them unnecessary for stack-allocated values (or other optimisations).

### Positive

- Copy-on-write (COW) avoids unnecessary copying.
- Indirected substructures can be reused with COW.
