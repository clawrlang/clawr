# ADR-003: Ternary Fields on Binary Hardware

[ADRs](./README.md)

## Status

💡 **Proposed**

> An idea to be considered for adoption

## Context

Binary and ternary computers are fundamentally incompatible. To communicate, the ternary systems will have to understand binary data or the binary systems must understand ternary.

## Decision

Bit-fields and trit-fields are separate types that are both available regardless of platform.

## Rationale

1. [ADR-000](./adr-000.md) mandates platform agnosticity
2. Reading ternary data on a binary computer (and vice versa) should be possible
3. Ternary computers are not yet commercially available. Ternary storage might be made available earlier.
4. Supporting binary fields on ternary chipsets is trivial, supporting ternary on binary is possible through emulation.

> [!tip]
>
> Ternary fields can be emulated using two separate binary fields. One bit from each field (in the same relative positions) would emulate the same ternary bit (or trit). This makes it easy to perform lane-wise operations using standard bit-wise operations.
>
> Two bits model four states — not just three — so one state per position would have to either be considered invalid or equal to another.

## Alternatives Considered

- Allow ternary fields only on ternary platforms. Allow binary fields on both.

## Consequences

### Positive

- Code can be made more reusable
- Binary computers can understand raw ternary data

### Negative

- Ternary fields require emulation on binary
