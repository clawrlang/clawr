# ADR-039: Control-Flow

> Status: ✍🏼 Draft

## Context

A general-purpose programming language needs control-flow mechanics.

This separates procedural languages from declarative languages. A declarative language like VHDL or Haskell declare truths that must be fulfilled at all times (“invariants”). It cannot describe interactions except in the shape of data structures. A procedural language defines operations that a program may perform and the algorithms that ensure that the invariants are maintained throughout execution.

Clawr supports three-valued truth. This affects how control-flow is defined. According to [ADR-006](./adr-006.md), the `ambiguous` state is not `true` and should be considered `false` in control-flow statements. But so should `!ambiguous`, because `ambiguous` is not actually `false`.

## Decision

### Implemented Subset

The implementation supports `if`/`else`, `while`, `repeat`/`while`, and three-valued logical negation. Their current rules are defined in [Control Flow](../spec/language/control-flow.md), with CIR contracts in [`IF`](../spec/cir/statements/IF.md), [`LOOP`](../spec/cir/statements/LOOP.md), [`NOT`](../spec/cir/expressions/NOT.md), and [`SCOPE`](../spec/cir/expressions/SCOPE.md). Source short-circuiting is encoded by the frontend; CIR `AND`/`OR` are eager.

### Draft Extensions

The remaining designs below are not current language rules.

The draft proposes `for`-`in` loops (as Swift), not C-like `for` loops.

```clawr
for const x in xs { print(x) }
```

The draft also proposes switching (both as expression and as statement) with pattern-matching using the keyword `match` or `when` and the double-arrow symbol, `=>`, which are more compact than `switch`/`case`, yet equally readable.

Unlike C, switch blocks do not “fall through” by default. Each case is independent, and only the matching case is executed. Swift allows explicit fallthrough with the `fallthrough` keyword, but Clawr does not support this feature. To compensate, perhaps, multiple patterns can be combined in a single arm using commas.

```clawr
// Expression-style: `when` - each arm must be an expression
const v = when t is {
    true => 1
    ambiguous => 0
    false => -1
}

// Statement-style: `match` - each arm is a block of statements
match t {
    true: { print("it's a given!") }
    ambiguous: { print("who knows anything really?") }
    false: { print("no way, no how!") }
}

match num {
    1: { print("a single") }
    2: { print("a couple") }
    < 5: { print("several") } // Pattern matching with relational operators - also works for `when` expressions
    _: { print("many") }
}
```

Speculative ideas:

Note that a truthvalue (`t`) can also be `ambiguous`, which is neither `true` nor `false`.

```clawr
// Quaternary operator? Might be a tad too innovative for now
const x = t ? "true" ~ "ambiguous" : "false"
const y = t ? "true" : "ambiguous or false"

// Guard statements for early exit based on truthvalue conditions. The block must end with an exit statement (`continue`, `break`, `return`, etc.).
// Only `true` statements are accepted by the guard; `false` and `ambiguous` are not.
guard t or { return } // Exit if `t` is false or ambiguous
guard t != false or { return } // Exit if `t` is false only

// Should also be possible to match `data` structures and `union` types with patterns.
match structure {
    {value: 1}: { print("a single") }
}

match unionValue {
    CaseA: { print("matched CaseA") }
    // speculative string interpolation syntax
    CaseB { prop1: x, prop2 }: { print("matched CaseB with prop1: \(x) and prop2: \(prop2)") }
}
```

Note that [string interpolation](./drafts/string-interpolation.md) is not yet implemented. The syntax is yet to be decided. The example above borrows from Swift.

## Rationale

- C-style `for` loops emphasise implementation, not intent, and they a prone to off-by-one errors.
- The `switch`/`case` syntax feels heavy (personal opinion). There might be a valid argument for claiming that it is verbose and that it emphasises code structure over programmer intent. The segregation between `match` and `when` helps distinguish between statement-style and expression-style control flow, making the programmer's intent clearer.
