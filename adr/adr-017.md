# ADR-017: Inheritance Allocation

> Status: ✅ Adopted

## Context

Constructors in other languages have complex rules. The super-constructor typically must complete before the subclass constructor is allowed to perform any operation — including initializing its properties.

That means that the super-constructor executes on partially initialized memory and executing abstract/virtual method can cause undefined behavior.

## Decision

Clawr supports inheritance. The memory for the whole inheritance stack is allocated once. Properties are initialized from the subtype up to the supertype, and secondary setup then runs from the supertype back down to the subtype, so no operation ever runs on partially initialized memory.

> [!note]
> The rules themselves are defined in the specification: [Initialization and Inheritance](../spec/language/user-types/object-data.md#initialization-and-inheritance).

## Rationale

- Performing setup on partially initialized memory is complex.

## Consequences

### Negative

- New rules for initialization might be confusing.

### Positive

- It becomes impossible to execute operations on partially initialized memory.
