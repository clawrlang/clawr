# ADR-010: Serializable `data`

> Status: 📝 Proposed

## Context

Data structures are often used as DTOs or for persistence.

## Decision

Every `data` type is serializable by default, and a `trait` can customise serialization. No output format is assumed.

> [!note]
> The rules themselves are defined in the specification: [Rules for `data`](../spec/language/user-types/object-data.md#rules-for-data). This ADR records only the reasoning.

## Rationale

1. Persistence and communication (DTO/DAO) is the main purpose [^big-data] for a data structure. And serialisation is a fundamental strategy for that use case.
2. If encapsulated objects are persisted, it is assumed that the developer will want to define the strategy themself.

[^big-data]: Data structures actually exist to support **two** main use cases: the other case is easy readonly access for computations on — and filtering of — big data.

## Alternatives Considered

- Requiring explicit annotation and implementation for all serialized types.
- Requiring explicit annotation, but providing a default implementation based on declared properties (like Swift).

## Consequences

### Positive

- Simple and automatic serialization

### Negative

- The serialization protocol must be designed
