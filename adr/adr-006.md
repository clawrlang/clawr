# ADR-006: Three-valued Truth

[ADRs](./README.md)

## Status

✅ **Adopted**

> Principle is in use in the ecosystem, or the feature has been implemented in the example implementation

## Context

[Three-valued logic](https://en.wikipedia.org/wiki/Three-valued_logic) has many flavours. One canonical philosophy must be chosen for Clawr

The philosophical models of three-valued logic are defined by how they consider *material implication* — a problematic concept in its own right. You can however infer that [Stephen Cole Kleene](https://en.wikipedia.org/wiki/Stephen_Cole_Kleene) considered the third state **neither** true **nor** false, while [Jan Łukasiewicz](https://en.wikipedia.org/wiki/Jan_%C5%81ukasiewicz "Jan Łukasiewicz") considered it **both** true **and** false.

## Decision

The `truthvalue` type has three values/states: `true`, `false` and `ambiguous`. The `true`/`false` values are considered the same as their well-known Boolean counterparts. The `ambiguous` state is considered not quite `true` and not quite `false` (like the *Unknown* of Kleene logic). In control-flow statements, both `ambiguous` and `!ambiguous` are considered `false` expressions.

- Negation of `ambiguous` is `ambiguous` (`!ambiguous == ambiguous`).
- AND (`&&`) returns the “least true” of the inputs (`true && ambiguous == ambiguous`, `false && ambiguous == false`).
- OR (`||`) returns the “most true” of the inputs (`true || ambiguous == true`, `false || ambiguous == ambiguous`).

The runtime `MUST` short-circuit expressions on the form `true || x` and `false && x` just as is expected from binary logic. If the left hand side is `ambiguous` short-circuiting is not possible regardless operator.

This model is a close sibling to Kleene logic, but it cannot be said to be an implementation of it because in Kleene logic `ambiguous == ambiguous` would evaluate to `ambiguous`. We need it to be `true` so that we can handle all three states in branching logic.

> [!note]
>
> Kleene and Priest logics, and the Łukasiewicz Ł3, are defined by how they consider *material implication* — a problematic concept in its own right — rather than what the third state *means* according to their respective philosophies. It is therefore not quite true to say that this is an implementation of Kleene logic even though the idea that the unknown/ambiguous state in both cases is considered neither true nor false.
>
> Unlike the Ł3 which considers the unknown state **both** true **and** false.

## Rationale

- [ADR-000](./adr-000.md) mentions ternary computing as the original inspiration for creating the language. Ternary computers are expected to use ternary logic natively.
- `if (x)` naturally reads “if x is true,” rather than “if x is not false.” Treating `ambiguous` as sort-of-`true` feels incorrect.
- Short-circuiting is expected based on the prevalence of prior art. When the first part of the expression evaluates to the Boolean subset (not `ambiguous`), the logical conclusion will closely match the binary model.

## Alternatives Considered

- the Łukasiewicz Ł3 is deemed not useful for automated decision-making, as `ambiguous` would be both `true` and `false` at the same time.
